# 上游百万级队列扩容、香港全站入口与 0.9.1 / sfe3 落地（2026-11-24）

## 近期上游变更与线上故障根因

自前一核对点 `646f70e637d1`（引擎 `8ce96e275dc2`）至当前线上版本 `afb54896+`（引擎 `95e3884615ee`、WASM `ba85cd8aae39`、数据包 `450ebd22f510`），上游主要有三类变化：

1. **服务端百万级密封订单入库与调度改造**：2026-11-23 至 2026-11-24 凌晨，上游导入大规模密封计算库存（总队列约 100 万行，按水位保持约 7,400～8,000 行活跃 `open`），并引入 `order_cut` 分区调度。扩容初期 `board_sync` 中的未结算 `states` 查询、逾期/非确定性审计与库存页构建锁发生数据库竞争，导致大量 `/api/board/sync` 耗时超过 30 秒。上游随后通过 `9edd1131c8`、`313fe0c21f`、`7f830f6f7d`、`e59debf0fc`、`c2a62f6c8b` 等提交收紧了查询边界。
2. **主站切入 Cloudflare 代理与香港完整入口（`cn.wfsim.app`）上线**：上游通过 `scripts/website_proxy.py` 将 `wfsim.app` 根记录切入 Cloudflare 代理，并通过 `deploy/hk-website.nginx` 将 `cn.wfsim.app` 升级为完整香港站点入口（承载 `/release.json`、`/pkg/*`、`/work.json`、`/stats/*`、`/api/board/demand`、`/api/appraise/*` 及匿名中继 `/api/board/sync`，其中中继 `proxy_connect_timeout 10s`、`proxy_read_timeout 60s`）。注意 `cn.wfsim.app/demand.json` 回退到前端 HTML，队列详情在香港入口由 `/api/board/demand` 提供 JSON。
3. **旧客户端放大超时与接不到任务的连锁机制**：
   - `simfleet 0.9.0` 仅向 `cdn.wfsim.app/work.json` 拉取任务信号；国内访问受阻时退化为 120s 盲询。
   - 首次请求在后台串行测速完成前默认直连 `wfsim.app`；且全局超时固定 30s、无独立连接超时。当服务端 `board_sync` 在 31～55s 内完成派单并写入 `next_at` 冷却时，客户端在 30s 提前报 `timeout: global` 中断，随即切向另一条线路再超时 30s，甚至在双路均失败时将线路翻转到不可达的直连地址；下一次空 `held` 重试又把服务端刚派发的整包租约释放并撞上 `early: true` 冷却，表现为“接不到任务 + 每约 3 分钟报一次 `timeout: global`”。

## 客户端 `v0.9.1` 与原生引擎 `sfe3` 落地项

- **网络与调度容灾（`src/net.rs`、`src/sync.rs`、`src/fleet.rs`）**：
  - 首次选路与双路故障恢复时并发探测 `wfsim.app` 与 `cn.wfsim.app` 并等待结果，后续每 10 分钟后台无感刷新。
  - 连接超时设为 10s，榜单/中继 POST 全局超时设为 65s（覆盖香港入口 60s `proxy_read_timeout`）；双路均失败时不翻转已知可用线路，并优先保留服务端真实 HTTP 状态码。
  - `/work.json`、`/release.json`、`/pkg/*`、`/stats/*`、`/api/board/demand`、`/api/appraise/*` 全部支持无 Cookie 双入口自动回退；信号与队列快照允许 10s 正向时钟容差以兼容 HTTP `Date` 秒级截断。
  - 侧栏接入新 `demand` 队列快照（含过期时间）与实时可派行数。
- **计算与并行优化（`native-engine` `sfe3`、`src/engine.rs`、`src/fleet.rs`、`src/work.rs`）**：
  - 紫卡搜索跟进上游 `quickScoreWidth` / `quickScoreSlices` 自适应切片、`compact_shards: 1` 紧凑分片，以及 `split_finals`（`verify_final` / `finish_finals`）多核并行决胜验证。
  - `tools/build-native-engine.ps1` 识别上游已内置的 `inline-single-worker`、`prepared-optimize-plan`、`deferred-lead-reports`、`bounded-lead-metadata` 与 `split-finals`，恢复 `SFE_INLINE_OPTIMIZER=1`。
  - `native-engine/src/board.rs` 仅在连续分片实际合并时执行累加器精度检查。
  - 原生修订号升至 `sfe3`，加载器按 `sfe3 -> sfe2 -> legacy` 顺序自动兼容回退。
