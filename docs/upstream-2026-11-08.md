# 2026-11-08 上游性能更新与本地适配

当前线上引擎 `69219ccb033d`，官方 WASM `7d59d2968031`，数据包仍为 `bb069d7aba3c`。干净上游提交 `1db552fa9157817113029fa6bed9950caad1a431` 计算出的引擎号与线上一致。本轮仅处理 CPU 引擎，不构建 GPU。

## 这次更新的实质

上游 `9016c1896` 将请求准备过程抽成公开 `PreparedSimulation`。榜单批次现在每个调用只准备一次，再按原始 run 索引计算；旧路径逐个 run 重复解析、准备。它还让面板与紫卡类别借用静态目录字符串，MOD 池按有限目录 ID 缓存，避免反复 `Box::leak`，并对几个战斗访问函数做内联。这些改动与本项目原有 prepared-board 和静态元数据优化目的重合。

上游 `a7ec2baf3` 新增官方原生 PGO：独立训练/留出数据，对完整结果做一致性校验，再按留出计时决定采用 baseline 还是 PGO；引擎身份新增构建输入（Cargo.toml/lock、PGO 脚本与训练/验证语料）。本项目的引擎 ID 工具运行该提交的可达哈希定义，已经正确得出新号，无须维护另一套硬编码哈希规则。

上游曾提交工作量单价校准，随后 `edb6e6130` 明确将积分政策与性能发布分离。当前 `GAS_PRICE_PER_MILLION=50000`、`RUN_PRICE=400000` 与前版相同；客户端本来也使用引擎返回的 `work`，不需要换算或手改积分权重。

## 我们需要同步改什么

需要修改原生包装和构建适配，客户端协议暂不需要变化。

- 新版直接用上游公开 `PreparedSimulation` 保存不可变准备状态；每个 run 单独生成 shard，再沿用本项目的浏览器数值归一化、顺序合并和 DLL 批次 ABI。
- 新版不再套入旧 `001-prepared-board.patch`，也不重复套入已由上游实现的 `003-static-panel-metadata.patch`。旧版没有这些接口/修复时，仍按原路径应用必需补丁。
- 构建脚本先检查公开接口，以及静态字符串、MOD 池、递归 metadata 传递与紫卡类别借用这些完整实现条件。未知或只完成一部分的迁移不予豁免，仍走必需补丁失败保护。
- 构建清单增加 `upstream_features` 与相应源码哈希，能区分“由上游提供优化”和“本地补丁被关闭”。
- 保持 Windows PGO v3、Linux baseline/v3 与 Apple silicon 构建，以及现有 native ABI。新 engine ID 独立发布，因此不需要客户端升级或重新命名历史 DLL。

本项目仍保留跨多个线程的整行准备状态、DLL 内分片合并、每路线程预算与接单调度；上游 `/api/board/runs` 的批次内准备复用不等于这些客户端能力。官方 PGO 选择流程没有未经评估替换本项目既有 PGO v3 路径。本轮不对相对官方/旧版的吞吐作百分比承诺。

可选旧紫卡缓存补丁 004/005/006 仍跳过，其候选身份规则已由上游重构；此次未扩大搜索算法改动。协议仍为 8，board/order/runs/fold/score 形状、quick_fleet 和提交工作量合同兼容。新完整报告任务仍要求主动声明能力，客户端没有声明，不能仅添加能力标志冒充支持。

## 必要核对

用当前与前版干净源码检查功能选择，新版识别两项上游替代，前版继续走补丁。运行既有两个原生用例：逆序/并行分片与普通接口答案一致；普通、组合与递归攻击面板和紫卡类别确实复用静态元数据。随后三平台正式构建继续执行 8 行榜单分数/work/gas 及紫卡 canary 的 WASM 一致性核对。不运行客户端全量测试，不构建 GPU。
