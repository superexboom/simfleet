# GPU 私有状态与页表优化

目标：在相同的 CPU＋GPU 提交上限内减少每局状态开销，提供更多并行模拟，最终以完整任务吞吐判断收益。运行数量、随机种子、gas 计数、浮点行为和评分顺序不变。

旧 sfg1/2 使用 4 KiB 写时复制页和 32 位平铺页索引。新实验 sfg3 使用 1 KiB 私有页与 16 位索引，减少只写页内少量数据时的额外复制。旧包按旧布局执行，不能把新页表交给旧内核。

两种 sfg3 变体分别验证：

- 平铺页表：每个 1 KiB 虚拟页保留一个 16 位索引。缩小索引不能完全抵消页数增加，必须把页表一起计入预算。
- 稀疏页表：顶层按 64 KiB 区域索引，只给发生写入的区域分配 64 项下级表；下级表放在有上限的私有页池中，既不另开无界分配，也不漏计内存。未写区域直接读共享快照。

私有页池仍最多约 3 GiB。新包最多 32 行 / 32000 次模拟；实际批量继续取 CPU＋GPU 提交预算、系统可用内存、显存和故障缩批限制的最小值。旧包维持最多 16 行 / 16000 次。worker 报告页大小、索引宽度、映射区域大小，客户端验证布局后才使用相应的探测配额。

探测记录中的页数按实际页大小换算，不把 1 KiB 页误当成 4 KiB 页。新页布局加入 64/96/128/160 KiB 配额；资源不足后提高的配额下限仍保留。更换模块会使绑定更新并重新学习，已有格式不会静默误用。

验证沿用已有 CUDA 内存差分工具，覆盖未对齐、页边界、重叠复制、WASM 内存增长、gas 部分访问和资源耗尽；采用原始任务完整分片与最终评分对照。只有内存下降不足以证明可部署，仍需测量相同任务的完整时间。

固定旧引擎 `5c64c380e5f2` 的 Burston＋Furis、4000 次完整模拟中，4 KiB 版最大私有状态 184 KiB；1 KiB 平铺版为 119 KiB，稀疏版包含下级索引为 127 KiB。4000 线程平铺细页表占 220,160,000 字节，稀疏顶层目录占 3,440,000 字节。平铺版耗时 12.673 秒，稀疏版 15.539 秒，全部分片、gas 和评分一致。稀疏查询增加的代价不能忽略，需要与更大批量的吞吐一起判断。

相近私有页池预算下，旧版 12000 次模拟耗时 16.608 秒；平铺细页版 18000 次耗时 19.328 秒，每秒模拟吞吐高约 28.9%；稀疏版 18000 次为 22.872 秒，高约 8.9%。三者完整分片和评分一致；整个串行对照进程族提交峰值约 6.73 GiB。稀疏页表的额外查询抵消了部分内存收益，因此下一步完整客户端验证优先使用平铺细页版。

## 完整客户端对照

同一引擎、五种武器六类构筑混排，240 行每行原始 1000 次模拟；Ryzen 7 9700X 配置 8 个 CPU 线程、RTX 5080 / 驱动 616.92、8192 MiB 合计提交上限、空 GPU 学习缓存。时间包含 GPU 初始化、探测、任务分流与合并；启动前 CPU/WASM 参考校验不在 REPLAY 计时内。

| 指标 | preview.13 / sfg2 | preview.14 / 平铺 sfg3 |
|---|---:|---:|
| 完整行数 | 240 | 240 |
| 完成时间 | 129.530 秒 | 111.305 秒 |
| GPU 完成行数 | 60 | 87 |
| GPU work | 435956033652 | 534194489682 |
| 进程族提交峰值 | 6.31 GiB | 7.12 GiB |
| 故障回退 / worker 重建 | 0 / 0 | 0 / 0 |

总 work 同为 `1969443637200`，评分、metric、work 的完整多重集合相同。整机吞吐提高约 16.4%，同一墙钟区间内 GPU 分账吞吐提高约 42.6%。这是一轮固定离线队列对照，不能直接预测变化中的线上任务，也不是新上游引擎的性能对照。选定平铺 sfg3，稀疏版保留为研究路径。

新版这一轮 GPU 的 work 为 CPU 的约 37.2%，尚未达到 CPU 一半。该比例取决于任务构成、CPU 线程预算及 GPU 能实际领取的行数，不能当作两种硬件的通用性能比。批量扩大会提高峰值提交，因此这次目标是在 8 GiB 上限内提高吞吐，不是降低整机内存峰值。显存与 Windows 进程提交单独统计。

开发期间生产引擎自动更新至 `dac6ecbaf97e`，已核对发布原生 DLL 的来源为 `4af28da691a2615831432e56af6319dcff9ab800`。性能比较固定旧引擎，不能混用更新前后的数据、评分或任务成本。生产最终套件必须另行匹配当前引擎。

当前引擎的首次完整验收发现，18 行 Furis 批次会撞上旧的固定 30 秒超时。sfg3 的批次超时改为 `clamp(runs × 30 秒 / 8000, 30 秒, 120 秒)`，18,000 次为 67.5 秒，准备与合并也计入这一总时限。探测仍为 12 秒，旧布局仍为 30 秒。沿用现有超时用例增加边界断言，只重跑失败的当前引擎验收；前述 240 行性能对照未发生超时，不重复运行。

修正后，当前引擎的 96 行 Burston / Furis 完整验收全部与原生参考一致，GPU 完成 18 行，完整时间 45.376 秒，GPU 无回退、无重建，进程树提交峰值 6.42 GiB。这组数据用于当前引擎兼容验收，不与旧引擎的 240 行性能对照混算。sm120 模块 SHA-256：`a3f3a4caf6b9b50512621098ff400dd9bc2d2d0bb4f28e8a348435868f9a8e9e`。

机器可读结果、输入指纹和模块标识保存在 [`private-pages-results.json`](../experiments/gpu-board/private-pages-results.json)。复用 GPU 构建脚本时，选择 `--revision 3 --cow-page-bytes 1024 --architecture 120 --block 32 --max-registers 96`，其余源代码、原生参考 DLL 和工具链参数按原有流程提供；不传 `--sparse-page-map`。
