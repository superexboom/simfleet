修复榜单任务很快算完后，自动并发无法补足空闲核心的问题，并细化领取任务的等待原因。

- 某一路刚获得过任务、很快算完、仍在等待服务器允许下一次领取时，也可触发既有并发上限内的自动扩容。此前必须每一路还拿着任务才允许扩容，快任务反而容易空等。
- 设备绑定在后台进行，与任务信号并行；某一路绑定慢不再堵住全局派单、任务完成处理和其他路的续租。该路仍先完成绑定再领取。
- 等待服务器领取间隔期间按正常频率刷新 CDN 信号，到点可以直接使用新鲜信号；信号 HTTP 超时为 5 秒，失败后仍使用原来的直接询问回退规则。
- 任务信号不可用不再阻止已经到期的结果提交。初次普通状态上报不会抢在有任务信号的领取错峰等待之前发出。
- 界面分别显示绑定设备、请求任务、领取间隔倒计时、服务器未分配、网络重试、信号不可用、排空和引擎切换，减少笼统的“等待任务”。
- `dispatch.log` 记录请求耗时、收到的行数、服务器 `next_ms` 和调度参数；不记录账号、令牌、计算者 ID、任务正文。后台写入并限制为两个约 1 MiB 的文件。

服务器的每身份领取间隔、每包上限和任务分配条件继续遵守。客户端修复不能保证任意时刻都有可分配任务。
