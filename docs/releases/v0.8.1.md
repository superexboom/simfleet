本版包含长期运行内存维护、原生引擎吞吐优化、NUMA/缓存拓扑调度，以及紫卡 lead 优化。

- 修复本地引擎热路径的重复永久分配；线程退出完成后再卸载 DLL。内存持续超出软线时排空任务、保存状态并有序更换进程，保留正常暂停和退出行为。
- 榜单任务共享一次准备好的战斗参数，原生分片在 DLL 内按原运行索引合并，减少 JSON 往返、分配和搬运。
- 紫卡 lead 跳过待评分轮次中必定丢弃的报告，有界缓存配装 key 和排序资料。缓存每表最多 4,096 项，新搜索重置，线程退出释放。
- 支持 `placement=auto/system/numa/cache`、`numa_nodes` 和 `cpu_offset`，优先物理核心，识别 Windows 处理器组、NUMA 节点与末级缓存；提供多实例的明确核心划分。
- 原生构建使用独立修订号 `sfe1`，新客户端会优先获取新版库；Windows x64/AVX2、Linux x64/AVX2、macOS arm64 的构建均保留 WASM 对照关卡，并发布 SHA-256 和补丁来源。

固定请求实测（Ryzen 7 9700X）：紫卡搜索 25.68 → 2.47 秒，103 步、20,880 场和完整答案/work 一致；12 行榜单加 1 个紫卡的混合回放 34.58 → 14.66 秒。收益取决于工作负载，不能推算所有任务都快十倍；尚未在 Xeon Platinum 或 X3D 实机验证调度增益。40 次重复搜索内存检查通过，不能代替连续一到两天的部署观察。详见 [实现和验证记录](https://github.com/superexboom/simfleet/blob/v0.8.1/docs/riven-lead-0.8.1.md)。

升级前退出旧进程，再覆盖程序文件，保留 `simfleet.toml`、`cache/` 和 `kept/`。Windows 的 `-native.zip` 附带本版原生库；普通包会在运行时自动下载对应原生库。独立 DLL 放入程序旁的 `engines/` 目录，保留下载文件名；AVX2 CPU 使用 `-v3`，旧 CPU 使用基线版。网页引擎更新后，客户端继续按网站引擎 ID 选择通过校验的库。
