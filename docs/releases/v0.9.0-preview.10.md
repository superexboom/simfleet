修复高内存配置未传入 GPU 子进程，以及资源超限后提高的单局配额被后续小样本探测降回的问题。

- `S → CPU+GPU上限 MiB` 现在同步传给 GPU 子进程，重建 worker 也保留设置。父进程继续执行 CPU＋GPU 合计提交硬上限，另留 64 MiB 给监督进程；子进程不再固定卡在 8 GiB。设置 65536 MiB 是允许的总提交上限，不是预分配 64 GiB 显存。
- 单局私有页不足（状态 120）时，同场景后续任务逐档提高私有页配额并缩批，当前失败行仍交给 CPU。新探测不能把已经提高的配额降回；到达现有单局上限后暂缓。
- 超时、进程异常和输出范围限制不再无差别翻倍私有页配额。界面分别显示“单局私有页不足（120）”与“输出/地址范围超限（2）”，资源回退的原请求和配额保存在有大小上限的 `gpu-diagnostics/last-resource-fallback.json`。
- 探测 8 秒、完整批次 30 秒的执行超时仍保留，它们与 RAM 总限额独立。高配置机器也可能遇到复杂场景的慢探测；不能仅凭剩余内存或显卡型号判定这些超时是内存不足。

现有 PGO DLL 与 sm75/sm89/sm120 GPU 套件继续使用，只需更新客户端。保留 preview.9 对低可用内存主机的缩批修复，贡献校验与 CPU 回退路径不变。
