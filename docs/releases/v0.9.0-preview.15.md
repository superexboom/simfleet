修复长时间运行后 GPU 重复探索慢场景、完整批次反复超时的学习策略，并补充 CPU 低占用诊断。

- 小样本探测通过不再清空完整批次的失败次数。连续失败的场景逐步延长暂缓时间，真正完成且有收益的完整任务才清除失败历史。
- 探测间隔按成本增加，并保存到学习缓存。成功探测后间隔至少 15 秒、成本的四倍，最高 120 秒；不划算或超时的探测至少等待 60 秒。重建 worker 仍保留间隔，已经学会的完整任务可立即运行。
- GPU 超时或 worker 故障交回 CPU 的正常任务行计入回退数；探测不增加完成数或回退行数。派发日志里的探测次数按实际 8 次记录。
- CPU 实得核心不足预算一半且手中仍有任务时，dispatch.log 记录预算、待完成线程、GPU 持有行、待展开行和同步状态。超过 200 ms 的调度调用记录 CPU 填充与 GPU 调度耗时，帮助区分任务供给、调度阻塞和执行线程等待。

GPU 速度口径保持按实际活跃时间计算，包含探测和失败成本；无任务和暂停期间冻结。此次客户端修复未提高超时上限，也未改变 sfg3 接口。同一上游引擎的 GPU 套件可继续使用；上游引擎变化后，需要换成匹配新 engine ID 的套件。

当前配套引擎为 `6c720edfd739`：已修复上游缓存重构导致的原生构建失败，[CPU 原生引擎](https://github.com/superexboom/simfleet/releases/tag/engine-6c720edfd739)会自动下载；[NVIDIA sfg3 套件](https://github.com/superexboom/simfleet/releases/tag/gpu-6c720edfd739-sfg3)提供 sm120、sm89、sm75 三个独立包。sm120 已在匹配硬件运行验证，sm89/sm75 为交叉编译。客户端包仍为原有五文件，引擎与 GPU 套件分别发布。

带紫卡的固定构筑榜单可以走 GPU，紫卡增益搜索仍由 CPU 执行。详见[本次上游兼容与验证说明](https://github.com/superexboom/simfleet/blob/main/docs/upstream-2026-10-25.md)。

问题现场：十分钟内发生 6 次 GPU 超时重建；另一次按日志回算的最近 600 秒 GPU 活跃时间中，成功完整批次约 231 秒，失败完整批次约 120 秒，探测约 249 秒，有效速度约 48.8 分/活跃分钟。CPU 随后 24 秒采样为约 7.4–9.8 核，未复现用户先前报告的 1.2 核；本次不能将该历史瞬间认定为已修复。
