改进 CUDA 内存分配失败后的恢复，并移除 GPU 退出等待对 CPU 主调度的阻塞。包含 preview.9/10 的低内存缩批、配置预算传递及单局资源配额修复。

- `CUDA driver error 2` 是驱动层分配失败，与单局输出回退的状态 2 不同。错误现在记录 CUDA API；缓冲区分配失败还记录槽位、申请字节数、当前 free/total 和已保留缓冲量，便于区分显存、驱动和系统提交压力。
- 完整 GPU 批量分配失败后，将后续并行模拟数上限减半，最低一条正常任务，重建 worker 后继续保留该上限。全局分配失败不再把已学会的场景整体判为不适合 GPU；失败行仍交 CPU，实际显存和配置内存预算继续约束批量。
- GPU 进程终止后的等待在后台完成；旧 worker 未退出时不启动新 worker，避免资源重叠，CPU 调度继续运行。每轮优先派发已有 CPU 工作，再处理 GPU。
- 探测或启动阶段的分配失败仍按有限退避重试；每局资源、显存和执行超时各有独立限制，不会因 RAM 配置较大而取消正确性与资源保护。

本轮已跟进上游引擎 `5c64c380e5f2` 与数据 `102f454a0110`：同版 [PGO CPU DLL](https://github.com/superexboom/simfleet/releases/tag/engine-5c64c380e5f2) 自动下载，[sm75／sm89／sm120 NVIDIA 套件](https://github.com/superexboom/simfleet/releases/tag/gpu-5c64c380e5f2-sfg1) 需按架构手动更新。旧引擎的 GPU 模块不能用于新引擎。所有引擎仍独立发布，客户端压缩包保持原来的五文件结构。
