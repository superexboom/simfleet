# 上游引擎更新与自动构建恢复（2026-11-16）

## 已定位的自动构建故障

失败运行 `43705909031` 使用 simfleet `cb9c111809da150085df7bb144cb4241e8df2380`。Windows、Linux、macOS 全部在原生构建入口报 `BuildRoot must be a new dedicated directory`，发生在编译前；这不是引擎不一致，也不是三个平台分别有编译错误。

原生源码目录原先固定放在 `target/native-source-*`。`Swatinem/rust-cache` 恢复了 `target/` 中上一次保留的辅助源码，使下一次构建触发脚本原有的“不覆盖已有目录”保护。保持该保护，改为将临时源码放到 `RUNNER_TEMP/simfleet-native-<run>-<attempt>-<cpu>`，与编译缓存分离；`target/native-engine*` 和 `target/wfsim` 的编译缓存继续复用。

三个平台没有产物后，发布步骤还会重试下载不存在的 `engine-*` artifacts 并报错。现在先查询本次运行的可用引擎 artifacts；没有时正常跳过发布，真正的构建失败仍保留在对应作业中。

本轮沿用并核实了工作区已有的两项修复草稿；没有回滚其他工作目录。
